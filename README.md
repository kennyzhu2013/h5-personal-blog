# 我的博客

一个偏「内容 App」手感的个人博客。读者端是适合手机的 H5 信息流，也可在电脑上以居中阅读栏打开。文章一律以 HTML5 文件发布：在后台上传 `.html`，并可同时带上图片、样式、字体等附件，不必再使用富文本编辑器。

默认站点名称是「我的博客」，可在 `.env` 的 `SITE_NAME` 里一处修改。

## 功能

- 读者：首页信息流、按专题分栏（默认「技术」「生活」）、搜索（标题 / 摘要 / 标签 / 分类 / 正文纯文本）、收藏（保存在当前浏览器的 localStorage）、文章详情。首页和分类页可按「发布时间」或「最近更新」排序，选择会保存在当前浏览器。普通文章会显示预估阅读时长，正文有两个及以上标题时可以打开「目录」跳转；标记为 H5 游戏的内容会进入独立的游戏播放页（全屏、横屏提示），不展示目录和阅读时长。
- 后台 `/admin`：简单口令进入后，可保存草稿、预览、发布、改元数据和分类、上传或更新附件、下架或删除。已有文章会在编辑时自动保存草稿。编辑已发布的文章不会立刻覆盖线上内容。封面可以从已上传的图片附件中选择。
- 没有读者账号、评论、订阅通知和多作者。

## 环境要求

- Node.js 18 或更高版本

## 安装与启动

在项目目录中执行：

```bash
cd h5-personal-blog
cp .env.example .env   # 若还没有 .env，复制后改口令
npm install
npm start
```

`npm start` 会先构建前端，再在同一端口启动服务（默认 **http://127.0.0.1:3000**）。

然后在浏览器打开：

- 读者站点：http://127.0.0.1:3000
- 后台：http://127.0.0.1:3000/admin
- 专题页示例：http://127.0.0.1:3000/c/jishu （技术）、http://127.0.0.1:3000/c/shenghuo （生活）

首次启动会自动写入 3 篇示例文章（一篇技术、两篇生活），信息流不会是空的。其中技术示例带有相对路径的配图和样式，用来演示附件目录。

若你已经运行过第一版，直接启动即可：现有数据库会自动迁移，已有文章会视为「已发布」，示例文章会补上对应分类。不必手动删除 `data/blog.db`。

### 开发模式

前后端分开热更新（前端开发服务器在 5173，并代理接口到 3000）：

```bash
npm run dev
```

开发时请打开 http://127.0.0.1:5173 。

若只想启动已经构建好的服务（跳过再次 build）：

```bash
npm run start:server
```

## 口令与配置

所有配置都写在项目根目录的 `.env` 中。可参考 `.env.example`：

| 变量 | 说明 |
| --- | --- |
| `SITE_NAME` | 站点名称，默认「我的博客」 |
| `ADMIN_PASSWORD` | 后台口令，必填 |
| `SESSION_SECRET` | 用于签发后台会话 Cookie 的随机字符串 |
| `PORT` | 服务端口，默认 `3000` |

解锁后台时，浏览器会拿到一枚 HttpOnly Cookie（有效期 7 天）。所有会改动数据的后台接口都需要这枚会话。退出登录可在后台点击「退出」。

请不要把 `.env` 提交到 Git。仓库里只保留 `.env.example`。

## 如何发布一篇文章

1. 用你习惯的方式写一份完整的 HTML5 文件（可以自带 CSS，并用相对路径引用图片、样式、字体等）。建议正文不要再做一套网站导航，以免和阅读页顶栏重复。
2. 打开 `/admin`，输入口令。
3. 点击「写文章」，填写标题（必填），摘要、标签、分类可选。分类决定文章出现在哪个专题页；标签只用于检索和展示。分类可在「技术」「生活」中选择，也可输入新的专题名称。
4. 上传 HTML 文件；如有配图或样式，一并上传附件（可多选文件、选择文件夹，或上传一个 zip）。如果这是一款 H5 游戏，请勾选「这是 H5 游戏」。
5. 封面可单独上传，也可从已有图片附件中选择。
6. 先点「保存草稿」。已有文章在修改标题、摘要、标签、分类等字段后，大约两秒会自动保存草稿（不会自动发布）。保存后可以打开「预览」。
7. 确认无误后再点「发布」。只有这一步会让读者看到文章。

编辑一篇已经发布的文章时，标题、正文、附件和分类的改动都会先进入草稿，不会立刻覆盖线上版本。后台列表会标出「已发布 · 有未发布的修改」。预览看到的是草稿；「查看线上」看到的是读者正在读的版本。再次点击「发布」或「发布修改」后，草稿才会替换线上文章。

下架后读者端不再显示该篇，草稿仍保留，之后可以重新发布。删除会同时去掉正文和该篇的全部附件，删除前会再次确认。

没有分类的文章仍会出现在首页「全部」信息流里，只是不会出现在某个专题页。

## 数据目录

运行后的数据保存在 `data/`：

- `data/blog.db`：文章元数据、草稿版本和分类（SQLite）
- `data/revisions/`：每一版正文 HTML 及其附件（按版本分目录）
- `data/covers/`：封面图
- `data/posts/`：第一版遗留的 HTML 文件，迁移后不再作为正文来源
- `data/tmp/`：上传时的临时目录

这些目录已在 `.gitignore` 中忽略。示例文章的源文件在 `seed/`，第一次启动（或数据库尚无初始化标记）时会复制进去。若要强制重新写入示例数据：

```bash
npm run seed -- --force
```

注意：`--force` 会按原 slug 覆盖那三篇示例（包括分类和演示附件），不会删除你后来自己发布的文章。

## 文章是如何展示的

上传的 HTML 若是完整文档，系统会抽出 `body` 和其中的样式，在文章详情里用沙箱 iframe 展示，避免和站点外壳叠两层导航。正文和它的附件在同一个网址前缀下提供，因此 `./img/foo.png`、`style.css` 这类相对路径可以自然生效，不必依赖 `<base>` 标签。

iframe 使用 `sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"`，**不会**同时加上 `allow-same-origin`，因此即便正文里有脚本，也不能访问父页面或后台 Cookie。文章目录通过 iframe 向父页面发送标题大纲，并由父页面滚动到对应位置，不会读取 iframe 内部 DOM。链接仅保留 `http` / `https` / `mailto` 以及安全的相对路径，`javascript:` 一类地址会被去掉。上传的 `<base>` 标签仍会被移除。压缩包里的绝对路径、`..` 和符号链接会被跳过。

草稿预览使用带有随机令牌的专用地址，不会出现在读者的信息流或搜索里。

## 技术结构

- 后端：Node.js + Express + better-sqlite3
- 前端：Vite + React
- 生产环境由 Express 同时提供 API 和构建后的前端页面
